## 범위

속성과 카탈로그가 준비된 대표 공종으로 진행합니다. 토량은 Civil 3D 산출 근거를 함께 확인하며 웹 개념도를 물량 근거로 사용하지 않습니다.


## 준비 자료

- 공종별 전달 모델·목록: Civil 3D/Revit 출력 경로와 파일 버전

- 수량 카탈로그·매핑표: 공종·단위·원본 속성·집계 범위

- 원본 산출표: 동일 버전의 Civil 3D/Revit 결과, 비교 기준


## 핵심 개념


### 파일 통합과 수량 중복

같은 객체가 원본 파일과 통합 파일 양쪽에 들어 있으면 중복 집계될 수 있습니다. 파일 목록·버전·원본 ID를 먼저 정리합니다.


### 형상 속성과 산정 규칙

길이·면적·체적·개수 중 무엇을 산정할지 공종별로 정합니다. 객체 체적이 계약상 설계수량과 항상 같은 것은 아니므로 적용 규칙을 분리합니다.


### 속성 없는 객체의 처리

수량 속성이 없으면 자동 집계가 되지 않거나 매핑이 필요합니다. 누락을 0으로 간주하지 않고 원본 보완 또는 별도 산정 항목으로 관리합니다.

### 1. 모델 통합과 좌표·중복 확인

잘못 모은 모델에서는 수량도 틀립니다.

- 제공 전달 모델을 통합하고 기준 위치를 확인합니다.

- 원본 파일과 통합본을 중복 포함했는지 봅니다.

- 파일 버전·객체 수·원본 ID를 기록합니다.

확인: 좌표 정합과 파일/객체 중복


### 2. 공종별 검색세트 구성

수동 선택보다 재현 가능한 조건을 남깁니다.

- 공종·재료·형식 등 제공 속성으로 객체를 찾습니다.

- Search Set 조건을 저장하고 대표 객체를 확인합니다.

- 속성 없는 객체와 제외 대상을 별도 목록으로 만듭니다.

확인: 검색 결과의 포함/제외 근거


### 3. 수량 속성 매핑 후 대표 객체 산출

일괄 집계 전에 한 객체의 값이 맞는지 확인합니다.

- Quantification이 가능한 에디션과 프로젝트 단위를 확인합니다.

- 공종별 길이·면적·체적·개수 속성을 매핑합니다.

- 대표 객체 하나를 산출하고 원본 속성값과 대조합니다.

확인: 속성 이름·단위·측정 기준


### 4. 전체 집계와 원본 산출표 비교

차이를 줄이기 전에 원인을 분류합니다.

- 검증한 검색세트의 물량을 집계합니다.

- 같은 범위와 버전의 원본 결과와 비교합니다.

- 차이를 단위·중복·누락·산정 규칙으로 구분합니다.

확인: 수량 차이별 원인과 조치


### 5. 수정 모델 갱신과 결과 공유

변경 후에도 같은 기준으로 재산출합니다.

- 작은 모델 변경을 새 버전으로 반영합니다.

- 검색 결과와 산출 수량을 다시 확인합니다.

- 대표 화면·수량표·매핑표·미해결 목록을 공유합니다.

확인: 버전·ID·매핑·수량의 추적 가능성

## 교육용 사례

합계 40m가 나오는데 원본은 20m라면?

교육용 관 2개의 길이는 12m와 8m입니다. 원본 모델과 그 모델을 포함한 통합본을 모두 불러온 상황입니다.

같은 관이 각각 두 번 집계되면 (12+8)×2=40m입니다. 고유 원본 ID와 파일 포함 관계를 확인해 중복을 해소한 합계는 20m입니다. 실제 현장의 차이가 항상 중복 때문인 것은 아니므로 단위·범위·버전도 봅니다.


## 자주 발생하는 문제

- 객체가 보이는데 산출값이 없음: 수량 속성·카테고리·매핑과 단위를 확인합니다.

- 원본과 체적이 다름: 형상 변환, 제외 부위, 합산 범위와 산정 규칙을 대조합니다.
